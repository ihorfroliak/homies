| Target | Authenticated | Contact verified | Eligibility | Before | After |
|---|---|---|---|---|---|

## 2. Code seam

`backend/app/modules/trust/reports.py`: the shared `_validated(...)` takes an
explicit keyword `require_verified_contact`. `file_listing_report` passes
`True` (the gate stays first, before the target lookup — no oracle);
`file_message_report` passes `False`. The reason allow-list, text
normalisation, the 1000-character cap and the OTHER minimum are still run
for both. No other function changed.

**MESSAGE authorization preserved:** `conversation_access.side(...)` decides
"current side" before the reporter lock and again in the after-lock
recheck (tenant who started it, or a holder of MANAGE_MESSAGES now — baseline
semantics, `verified=False`; BP-9 untouched). SYSTEM and own messages 409;
strangers and missing messages the same 404. No message body is copied.

**Ordering consequence:** for MESSAGE the gate no longer precedes the lookup,
so an unverified caller now receives the eligibility answer any caller
receives (404 / 409 / 422 / 200 / 201). The SQLite test that pinned the old
"unverified stranger → 403" now asserts the stranger 404, identical to a
missing message.

## 3. Unchanged semantics

* **Quotas:** account-level and shared across target types (10 new per
  rolling 24 h, 20 live, `Retry-After`); an unverified MESSAGE reporter draws
  on them exactly like a verified one. No special quota.
* **Duplicates:** one live report per (reporter, target); a repeat answers
  200 `created:false` with the same report, no new row, no quota.
* **Locks/concurrency:** reporter row lock, listing `FOR KEY SHARE` before
  the conversation, after-lock access recheck, partial UNIQUE + savepoint —
  unchanged.
* **Moderator evidence:** reporter verification fields are read live and
  shown as they are; MESSAGE reports may now show
  `reporter_email_verified = false`, `reporter_phone_verified = false`.

## 4. OpenAPI

`403` on `POST /v1/reports`: "The account has no verified email or phone" →
"LISTING only: the account has no verified email or phone. A MESSAGE report
needs no verified contact (D-105)." Regenerated with
`python -m app.scripts.export_openapi`; frontend `schema.d.ts` regenerated by
`npm run gen:api` (parity only). No new stable code (none required).
